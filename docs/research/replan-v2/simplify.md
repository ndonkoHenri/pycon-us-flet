# v2 simplification review: keep / simplify / cut / later

**Date:** 2026-10-11.
**Input:** the frozen v1 docs in `../v1/`, checked against `pivot-brief.md` (binding) and the Zen of Python.
**Output:** one verdict per v1 mechanism. The v2 plan, architecture and AGENTS.md should be written from this list.

**Verdicts**
- **keep**: as in v1.
- **simplify**: same purpose, much less machinery.
- **cut**: not built.
- **later**: right idea, but in a later phase or only on real need.

**Assumed phases** (rename them to match the roadmap):
- P0: foundations
- P1: attendee core (the November demo)
- P2: polish, reminders, maps, accessibility
- P3: account and favourites sync (mock)
- P4: staff tools (mock)

**Zen tags used below**
- [simple]: Simple is better than complex.
- [flat]: Flat is better than nested.
- [explicit]: Explicit is better than implicit.
- [readable]: Readability counts.
- [one-way]: There should be one obvious way to do it.
- [explain]: If the implementation is hard to explain, it's a bad idea.
- [errors]: Errors should never pass silently.
- [practical]: Practicality beats purity.
- [never]: Never is often better than *right* now.

**Rule of thumb.** v1 built every mechanism for an outcome the pivot removed: a PSF-owned app in two existing store listings, plus a PWA, a handover and conference-week kill switches. v2 keeps what protects correctness and cuts what protected a release process we no longer have. These are never cut (§25): the time-zone rules, the feed-parsing rules, the exact signing bytes, the scan outbox, and the private-endpoint boundary.

**Flet APIs.** Every Flet API cited here was introspected in the local monorepo (`3f659615d`); the list is in the appendix.

## 25. Invariants that survive every cut

1. **Time:** aware instants; the year's TZ through `zoneinfo` + `tzdata`; one `clock.now()`; conference-local day buckets; tests under two machine TZs.
2. **Feed:** every `processData` rule with a named test; string and Ionic synthetic ids; a bad slot never blanks the schedule; the cache is replaced only after a good parse.
3. **Signing:** the exact `pycon-api.ts` bytes; one vector produced by Ionic's own code.
4. **Scans:** one outbox with owner, sponsor snapshot and door `idem_key`. Synced rows are kept. Network errors never count. Failures are visible. Logout is guarded.
5. **Boundaries:** secrets in SecureStorage; staff PII in memory only; the client structurally refuses private PSF endpoints.
6. **Material only:** no `adaptive=True`, no Cupertino controls.

## Appendix: Flet facts verified (local monorepo `3f659615d`; SDK reports 1.0.4)

- **Exist and are used above:**
  - hooks and routing: `use_context`, `use_state`, `use_effect(setup, dependencies, cleanup)`, `Route(…, modal, recursive)`;
  - services: `StoragePaths.get_console_log_filename`, `SemanticsService.get_accessibility_features`, `ShareFile.from_bytes/from_path`;
  - page: `Page.media.always_use_24_hour_format`;
  - controls and theme: `SnackBar` (a `DialogControl`), `NavigationBar.adaptive` (default `None`), `Theme(color_scheme_seed, color_scheme, page_transitions)`;
  - runtime and testing: `flet.utils.is_embedded()`, `flet test` with `FletTestApp` and `Tester.find_by_semantics_identifier`;
  - extensions: `flet_secure_storage`, `flet_permission_handler`.
- **Runtime behaviour:**
  - The build template sets `FLET_PLATFORM` and `FLET_APP_CONSOLE`.
  - A handler exception calls `session.error()`, which sends `SESSION_CRASHED`.
  - `flet` depends on `httpx`.
  - Dart builds `ColorScheme.fromSeed` and then applies the explicit `color_scheme`. There is no contrast-level option.
- **Absent:** `ft.RefreshIndicator`, `ft.use_route_search`, `Page.get_app_info`, a local-notifications package (#6948 is not in this checkout), `flet_barcode_scanner`.
