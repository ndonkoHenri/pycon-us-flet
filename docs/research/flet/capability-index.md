### corrections_to_reports
- ui-controls-map: `on_click=lambda: page.show_drawer()` (ion-menu-button row and section-3 shell) never opens the drawer. Truth: Page.show_drawer is async and the dispatcher only awaits coroutine functions, so the lambda's coroutine is never awaited. Same for `GestureDetector(on_double_tap=lambda e: iv.zoom(2.0))`. Use async def handlers or page.run_task. Evidence: flet/sdk/python/packages/flet/src/flet/controls/base_page.py:493, controls/base_control.py:516-552, controls/core/interactive_viewer.py:230
- ui-controls-map section 3: 'Each tab page component returns its own ft.View' while TabsLayout (outlet=True) also returns a View. Truth: under an outlet layout the layout returns the View and children return plain controls; doing both nests a View inside a View. Evidence: flet/sdk/python/examples/apps/router/nested_outlet_views/main.py (ProductsList returns Column, ProductsLayout returns View); components/router.py:504-536
- architecture-declarative-routing sections 2.5/9: 'Deep links GAP - no Flet API registers app links/intent filters'. Truth: flet build supports --deep-linking-scheme/--deep-linking-host and [tool.flet(.ios|.android).deep_linking] scheme/host, which write the Android intent-filter and iOS CFBundleURLTypes; only iOS universal links (Associated Domains entitlement) are missing. Evidence: flet/sdk/python/packages/flet-cli/src/flet_cli/commands/build_base.py:753-760,1421-1444; flet/website/docs/publish/index.md:1365-1450
- architecture-declarative-routing pitfall 2: 'Every route component under manage_views=True must return a View'. Truth: only view-level components not wrapped by an outlet layout, and modal routes (which never inherit layouts), return Views; children of outlet=True layouts return controls. The report's _redirect() used as index child under TabsShell returns a View and so nests a View in a View. Evidence: flet/sdk/python/packages/flet/src/flet/components/router.py:530,872-876
- architecture-declarative-routing section 9 rates Ionic Storage 'partial' and @capacitor/keyboard 'partial'. Truth: SharedPreferences + SecureStorage + sqlite/StoragePaths cover every storage use (services report agrees), and keyboard resize is default Scaffold behavior plus SafeArea/page.media, so both exist. Evidence: controls/services/shared_preferences.py, flet-secure-storage/src/flet_secure_storage/secure_storage.py, controls/core/safe_area.py
- ui-controls-map section 1.1 rates the ion-modal breakpoints sheet 'exists'. Truth: BottomSheet has no detent/snap fields (draggable, show_drag_handle, scrollable, fullscreen, size_constraints only), so it is partial. Evidence: introspection of ft.BottomSheet dataclass fields; controls/material/bottom_sheet.py
- ui-controls-map pull-to-refresh workaround A (`ScrollType.OVERSCROLL and e.overscroll < -80`) works only with clamping physics (Android). With iOS bouncing physics Flutter emits no overscroll notification and pixels go negative, so detect pixels < -threshold on UPDATE instead. Inferred from Flutter scroll physics semantics, not executed. Evidence: controls/scrollable_control.py OnScrollEvent fields
- Contradiction on interim barcode decode: ui-controls-map proposes Camera.take_picture() + zxing-cpp/pyzbar; services-native-gaps says it is not viable. Truth: no evidence in the repo/docs of mobile wheels for either (grep zxing|pyzbar in website/docs = 0), and pyzbar needs native libzbar, so treat it as unproven and use manual entry as the fallback. Evidence: flet/website/docs (no matches), flet-camera/src/flet_camera/camera.py:139,177
- Omission in all reports: ft.Markdown also supports LaTeX (latex_style, latex_scale_factor; Dart flutter_markdown_plus_latex), and flet_shadcn_ui (1.1.0) provides Toast, Sonner and Sheet(side=TOP|RIGHT|...). These are relevant to the top-toast gap, though Toast/Sonner have no position property. Evidence: controls/core/markdown.py fields, packages/flet/lib/src/controls/markdown.dart:3-61, flet-shadcn-ui/src/flet_shadcn_ui/overlays.py:64-200, types.py:142
- Flet repo nit (not a report error): router _split_chain_into_view_levels docstring says only pathless routes become layouts, but the code uses `not is_last and route.outlet`. The architecture report follows the code correctly. Evidence: flet/sdk/python/packages/flet/src/flet/components/router.py:504-534

### decisions / dated facts
- Declarative components mode: page.render_views(App) with ft.Router(ROUTES, manage_views=True). Agree.
- Route table mirrors Ionic URLs 1:1 (/app/tabs/...) so web URLs and future deep links stay identical. Agree.
- One outlet=True TabsShell layout owns AppBar + NavigationDrawer + NavigationBar and wraps every non-modal view. PARTLY WRONG: it sets leading=IconButton(MENU) on every level, which suppresses the implicit back arrow on detail pages, and its fixed title/actions lose per-screen titles and actions. It also omits the sponsor banner (View renders navigation_bar OR bottom_appbar). Fix: show the hamburger only on tab roots, and publish title/actions from screens via a context/observable ChromeState (or have screens return their own View through a shared Shell helper).
- List->detail modeled as parent->child routes so the list stays on the view stack; a shared SESSION child route is reused. Agree.
- Full-page modals (filter, lead note, floor plan, redemption) as Route(modal=True) + View(fullscreen_dialog=True); small sheets via use_dialog(BottomSheet). Agree (modal views escape layouts, verified).
- Redirects as components that navigate() in a mount effect. Agree, but under an outlet layout the redirect must return a control, not a View.
- State: @ft.observable AppStore/AuthState/Features/Prefs provided through StoreContext; services in ServicesContext via use_memo; feed_version counter for memo deps; favorites as list, not set. Agree.
- Async bootstrap in use_effect: prefs -> auth restore -> cache-first feed -> network refresh. Agree.
- Four themes (light/dark/HC-light/HC-dark) by swapping Theme objects into page.theme/dark_theme and forcing theme_mode; persisted in SharedPreferences with legacy-key migration. Agree.
- httpx.AsyncClient with Ionic-compatible sha1 signing and timeouts, behind a protocol so a Pyodide fetch client can be swapped in for web. Agree.
- Storage split: SharedPreferences for prefs, SecureStorage for key/secret, JSON file cache under StoragePaths (plus sqlite queue per services report). Agree.
- Global toasts via page.show_dialog(SnackBar); component-local toasts via a use_toast hook on use_dialog. Agree.
- Native gaps hidden behind protocols (Notifications no-op, BarcodeScanner with ManualEntryScanner fallback) so extensions can be swapped in later. Agree.
- Pull-to-refresh replaced by an AppBar refresh button + ProgressBar. Acceptable interim; a core RefreshIndicator is S effort and should land in Flet before the conference.
- Testing: pure pytest units for signing/parsing/stores, flet test UI tests with control keys, golden matrix of screens x 4 themes. Agree; disable theme animation for goldens.
- Deep links declared a GAP. WRONG: flet build has deep_linking scheme/host config; only iOS universal links are blocked by the missing iOS entitlements option.

### risks
- Staff tools (door check, swag pickup, lead retrieval, mask violation) cannot ship without a barcode extension; this is the only hard day-one gap (CAP-56).
- Push, local notifications and native calendar all depend on build-template hooks that do not exist yet (iOS entitlements, AppDelegate, Gradle plugins, manifest receiver/queries). Template forks right before a conference are a maintenance risk, so land flet-cli hooks first.
- No OTA: conference-week bugs need store releases unless reminders, menus, feature flags and announcements are server-driven.
- Background push cannot execute Python; design for OS-displayed notification messages only.
- Firebase Dart-only initialization on Android without the google-services Gradle plugin is unverified and needs a spike.
- mobile_scanner imports package:flutter/material.dart; pin the exact version and add an integration test for the material_ui gate.
- HTML->Markdown conversion loses tables and inline styles; sponsor and job-listing descriptions may degrade.
- Likely developer errors in components mode: conditional hooks (use_dialog, is_route_active) and sync lambdas calling async Flet methods (show_drawer, zoom, Clipboard.set). Add review checklist items.
- The web/PWA build lacks httpx, StoragePaths, push and local notifications, so its scope must be reduced.
- Python zoneinfo on iOS/Android may lack a tz database; bundle the tzdata package for America/Los_Angeles conversions (not verified in the repo).
- Material SnackBar cannot appear at the top; Ionic's top toasts will move unless a custom overlay is built.

### decisions / dated facts
- One pyproject.toml at the repo root with per-platform bundle IDs ([tool.flet.android].bundle_id = org.pycon.us, [tool.flet.ios].bundle_id = org.pycon.us.2023.onsite) so the app can ship as an update to the existing store records, if the PSF grants access.
- Version scheme YY.MINOR.PATCH in [project].version (27.0.0). One build number for both stores, computed in CI as YY*1000+MINOR*100+PATCH*10+RESPIN (27.0.0 = 27000 > 26022). Not stored in pyproject.
- No custom build template for v1. Fill the missing hooks upstream in flet-cli (iOS entitlements, Android queries/autoVerify, desugaring, resource meta-data, get_app_info) rather than fork. A pinned template fork is the fallback only.
- Android manifest additions that flet build cannot express (<queries>, asset_statements, FCM icon) go into a Flutter-only helper plugin (native/pycon_native_config) wired through [tool.flet.flutter.pubspec.dependencies], relying on Gradle manifest merging. Spike it first.
- Mobile-only extensions (barcode scanner, local notifications, add-to-calendar, firebase) are listed in [tool.flet.android|ios].dependencies, not in [project].dependencies, so the web build stays clean. Their imports are guarded, with Protocol/no-op fallbacks.
- Custom extensions live in the same repo under extensions/. They are wired with [tool.uv.sources] (editable, for flet run) plus [tool.flet.dev_packages] (for flet build), and published to PyPI once stable.
- Pin flet and the flet-* extensions to one exact released version. Never ship on a Flet prerelease, because the template would resolve the stable flet Dart package.
- CI: a PR workflow builds unsigned apk, ios-simulator and web. A tag-driven release workflow (protected 'release' environment) runs a matrix of aab (ubuntu), ipa (macos-26) and web with flet-dev/flet-build-action@v1, then uploads to the Play internal track, TestFlight (altool) and Firebase Hosting.
- The release workflow bakes build_info.py (VERSION, BUILD_NUMBER, GIT_SHA, TARGET) into src/ before building. It checks that the tag matches [project].version and refuses FLET_PAGE_URL or LAN dev URLs (the replacement for check-no-dev-url).
- Web: flet build web (not flet publish), base_url '/', route_url_strategy 'path', renderer canvaskit, CDN on. Hosted on Firebase Hosting with a ** -> /index.html rewrite and Cache-Control no-cache. Online-only PWA in v1 (offline is a GAP).
- Appflow live updates are replaced by a server-driven app-config.json (min_supported, latest, banners, feature flags) checked on start and resume, plus the existing 'New version available' banner linking to the store. Content keeps coming from conference.json. No Python OTA.
- Development loop: flet run (desktop) and flet run --ios/--android with the Flet companion app for UI work with hot reload; flet debug ios|android for native-extension features. A FLET_PAGE_URL dev client is an optional spike.
- Keep Android minSdk 34 (PSF policy) and set targetSdk 36 explicitly. Accept the fixed iOS 15 floor (wider than Ionic's 18).

### risks
- Store continuity depends on the PSF granting App Store Connect access (team BMM5U3QVKW, app id 6446810296) and the Play Console plus upload key for org.pycon.us. Without them the port becomes a new listing.
- Template-level gaps (iOS entitlements, Android desugaring, <queries>, App Links autoVerify) block push notifications, exact local notifications, password autofill and verified links. They need upstream flet-cli work by roughly March 2027, or a fork that must be rebased on each Flet release.
- App size: a minimal Flet APK measured locally is 55.5 MB (arm64-only), and an estimated 25-40 MB is downloaded from Play per device. That is several times the Capacitor app. The first Android launch also has an extra 'Preparing' stage.
- The web build runs on Pyodide: slower first load, httpx unavailable (the data layer needs a pyfetch transport), no offline service worker, and no notifications or filesystem.
- There is no PrivacyInfo.xcprivacy for the embedded CPython or the app target, so ITMS-91053 could appear on the first App Store upload. Unverified; test with an early TestFlight upload.
- Building on an unreleased Flet (1.1.0 dev) can cause 'Unknown control' mismatches, because the template resolves the stable flet Dart package. Ship on a released, exactly pinned version.
- Annual platform deadlines (the Xcode/SDK version App Store submissions require around April, Play target API around August) can force a Flet or Flutter upgrade shortly before PyCon in May.
- Workarounds marked PLAUSIBLE (helper-plugin manifest merging, the Gradle init script for desugaring, the FLET_PAGE_URL dev client, the MainActivity intent-filter merge) have not been built. Spike each one before depending on it.
- Android signing env vars must reach flet-build-action's composite steps. If they don't, Flet silently signs with the debug key. Verify the AAB signature in the first release run.
- Overriding NSAllowsArbitraryLoads appends a duplicate NSAppTransportSecurity key after the template's own. Verify the built Info.plist and run a smoke test on device.
- Exact-alarm policy: SCHEDULE_EXACT_ALARM is user-granted and off by default on API 34+, and USE_EXACT_ALARM is restricted by Play. Session reminders need an inexact fallback.
- The FLET_PAGE_URL dev-client approach recreates the 26.2.0 white-screen incident class if it reaches a release. The CI guard must stay.
