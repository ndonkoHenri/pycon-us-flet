# Feature matrix: all 263 Ionic features and their Flet disposition

Companion to [`PLAN.md`](../PLAN.md) section 4. First generated from the plan's disposition data; since D-130 this file is the source of truth and is edited directly, then re-checked by script against the canonical feature index (263 ids, each exactly once, no ranges; the check snippet is in [`backlog.md`](backlog.md) §14). Feature names and roles come from the index; the gotchas column condenses the cross-checked research (`docs/research/ionic/*.md`) and must be honoured by the implementation. Status as of 2026-10-11.

## Legend

**Dispositions**

- **port**: same behaviour, copy and data rules as Ionic, except small defect fixes stated in the notes column (each covered by the row's `test_<AREA>_<NN>_*`, D-98).
- **adapt**: same user outcome; behaviour deliberately changed (bug fix, platform idiom, data instead of code). The approach column says what changed. Every adapt row gets a test named after its id.
- **interim->upgrade**: ships at the milestone with the named interim; the upgrade turns on automatically when the named Flet piece is released and bundled (capability registry, PLAN section 5.7). Upgrade timing: G3 (2027-02-12) decides M3 vs 27.1 for E2/E3/E4; core items (U*) light up on the pinned Flet release.
- **defer**: not in 27.0 in any form. **None** in this plan: every non-dropped id ships something in 27.0.
- **drop**: not ported (2 ids, both with a reason).

Call fragments written with `await` are Flet service coroutines (decisions N1): call them from `async def` handlers or effects.

**Milestones** (dates in PLAN section 7): M0 foundations (to 2026-11-13), M1 CFP demo (to 2026-12-06), M2 attendee alpha (to 2027-01-31), M3 staff beta + native gates (to 2027-03-05), M4 2027 data + feature freeze (to 2027-03-31), M5 release (to 2027-04-30), 27.1 (to 2027-06-30), `-` dropped. Rows marked **T2** are should-haves on the cut list (PLAN section 4.1).

**Dependency codes**

- `CAP-xx`, `BLD-xx`, `ECO-xx`: rows of the Flet capability index (what Flet provides today, build/CI, ecosystem).
- `E1` flet-barcode-scanner (mobile_scanner 7.4.2), `E2` flet-firebase (firebase_core 4.15.0, firebase_messaging 16.7.0) + flet-firebase-analytics (firebase_analytics 12.6.0, a separate wheel bundled only if OD-3: one wheel has one fixed pubspec, so analytics cannot be optional inside flet-firebase and D-79 forbids an analytics SDK in 27.0; D-111, superseding D-24's analytics part), `E3` scheduled notifications in the official flet-dev/flet#6948 extension (flutter_local_notifications 22.3.1 + timezone 0.11.1), `E4` flet-add-to-calendar (add_2_calendar 3.1.1), `E5` flet-html (27.1), `E6` flet-slidable (27.1).
- `U1` RefreshIndicator, `U2` sticky headers, `U3` InteractiveViewer.set_transform, `U4` page.get_app_info, `U5` iOS entitlements, `U6` Android queries, `U7` desugaring, `U8` resource meta_data + string_resources (D-112), `U9` use_route_search, `U11` offline service worker, `U12` iOS deployment_target (only if spike S10 finds a pod above iOS 15), `U15` non-fatal handler errors (full list in PLAN section 6).
- `P1`-`P13`: PSF deliverables with needed-by dates (PLAN section 10.2). `S2` etc.: M0 spikes (PLAN section 7.2).
