# Feature matrix (v2)

**Status:** plan of record, 2026-10-11. **This file is the source of truth for every feature's disposition and phase** ([D-04](decisions.md)). It was generated once from the v2 planning data and is now **edited directly**: change a row in the PR that changes the behaviour, and say why in its notes. A change that contradicts a decision goes through a `needs-decision` issue first ([decisions.md](decisions.md), "How this record works").

It lists all **263** features catalogued from the Ionic app ([`research/feature-catalog.json`](research/feature-catalog.json), which also holds each feature's Ionic source and gotchas) plus our **9** additions `NEW-01`..`NEW-09`, each id **exactly once**. Ids are an inventory for traceability, not a contract: there is no "one test per id" rule and no parity gate (D-04). Issues cite the ids they cover (D-91). The plan is in [PLAN.md](../PLAN.md); the UX spec in [ux.md](ux.md); Flet gaps in [flet-gaps-and-extensions.md](flet-gaps-and-extensions.md).

`tools/check_matrix.py` (P0, [decisions §M](decisions.md#m-naming-binding)) checks that every catalog id and every `NEW-` id appears exactly once, uses the vocabulary below, that each row sits in its id's section and each section's row count is right, and that the counts tables below are current; run it after editing (`uv run python -m tools.check_matrix`), and it prints a stale counts table as it should be. `tests/test_check_matrix.py` runs it, so the local checks (`tools/check.sh`) fail on a stale matrix (#802). `--breakdown` also prints fuller breakdowns (by exact disposition, by section and phase), so they are not kept by hand here.

## Legend

**Dispositions** (D-04). Tags combine with `+`, e.g. `improve+interim`.

| tag | meaning |
|---|---|
| `keep` | Same behaviour and purpose; Ionic's copy and data rules are preserved. |
| `improve` | Same purpose, better UX/UI or behaviour; the UX change column says what improves. |
| `redesign` | The flow or screen is rethought; the approach column says how. |
| `mock` | Needs the private PSF `/api/v1`; built and tested only against our local mock (D-06, D-50, D-51). |
| `interim` | Ships a tested fallback now. A Flet core gap (U-items) is upgraded only by a PR that bumps the pinned Flet (D-64); an extension (E-items) is used when bundled and the app is embedded, via the import-time constants in `capabilities.py` (D-63), so the companion app always gets the fallback. |
| `later` | Part or all of the row deliberately waits beyond its phase; the notes say what and why. |
| `drop` | Not built; the row says why (PSF-only, push, OTA, web, or replaced by a better design). |
| `new` | Our addition, not in the Ionic app (`NEW-*`). |
