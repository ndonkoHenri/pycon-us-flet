# Decisions record (v2)

**Status:** plan of record, 2026-10-11. It replaces the v1 record (the PSF-oriented plan, D-01..D-136), which stays in git history (the repository's first commit) and is **not binding**. Binding input: the owner's direction of 2026-10-11 (community showcase, Android and iOS only, Material 3 only and identical on both platforms, not a 1:1 port, Zen of Python, phases rather than deadlines). Plan: [`PLAN.md`](../PLAN.md). Scope per feature id: [`feature-matrix.md`](feature-matrix.md).

**How this record works**
- Every decision is binding for code, docs and agents.
- Numbering restarts at D-01 for v2. v1 decisions are cited only as "v1 D-nn"; no live doc cites a v1 number against this file. From now on, numbers are never reused or renumbered.
- To change a decision, open an issue labelled `needs-decision` with the options and a recommendation, and settle it as D-101 describes (reversible choices don't wait for the owner). Then, in a PR merged before or together with the code that depends on it, add a new D-number and mark the old one "superseded by D-nn", or, when only part of it changes, "amended by D-nn" with the changed words struck through and the rest still binding.
- Decisions marked **prov. O-n** are provisional: they apply until open decision O-n is settled under D-101 (end of this file).
- `F1`..`F40` refer to the verified Flet facts in section N. Spikes `S1`..`S9` are defined in PLAN §8.

## Changes from v1

- **Purpose.** v1 aimed to ship as 27.0.0 of the PSF's store listings. v2 is a community showcase, so everything that existed only for the PSF is dropped: the PSF deliverables P1-P13, gates G1-G6 and the Track decision, Badge Days with PSF staff, Linear, outreach dates, PSF-held secrets and on-call.
- **Platforms.** Web and PWA are dropped (Pyodide transport, Firebase Hosting, offline service worker). Only Android and iOS remain.
- **Fidelity.** v1 kept Ionic's URLs, aria strings, exact colours, four-mode theme picker, Cupertino pickers and platform dark split. v2 redesigns in Material 3 (sections C and D).
- **Scope enforcement.** Gone: the 263 named tests, the `feature_trace` gate, the Node differential harness in CI, 168 goldens, the fallback-parity suite and contract tests against PSF staging. In their place: named rule tests, invariants and a one-off capture of Ionic's output (D-77).
- **Server-driven content.** `app-config.json`/`app-content.json`, kill switches, update gates and banner polling become bundled TOML year data (D-45). A content fix now needs a new build.
- **Push, analytics and Sentry** are cut. Local reminders are prioritised instead (D-58), with local logs (D-72).
- **Capabilities.** The observable `Caps`, CI manifest, API probes and remote veto become import-time constants (D-63).
- **Architecture.** 12 stores and 13 contexts become 3 stores (5 from P3). The service locator and provider families are gone. `@safe` plus a lint rule and a top-toast `Banner` become explicit error boundaries plus one small decorator until U15 lands (D-71).
- **Navigation.** The `/app/tabs` URLs, drawer, global floor-plan modal and short links become five fixed tabs, a flat More list and one recursive drill route (D-13..D-17).
- **Favourites.** Server-authoritative sync through the outbox becomes local-first sync with a dirty flag (D-55). The outbox goes from three retry caps to one (D-56).
- **Releases.** v1 had `27.x` versions, `YY*1000` build numbers, a `builds.txt` ledger, release/nightly/content workflows and a release train. v2 has SemVer `0.y`, commit-count build numbers, one CI workflow plus a weekly feed check and a manual APK build, and internal distribution (D-83..D-85).
- **Flet version.** v1 said "never ship on a prerelease; pin a released 1.1.x by 2027-03-05". v2 develops on a pinned 1.1 commit until 1.1.0 is released, because the owner's Xcode 27 needs it (D-81).
- **Planning.** The capacity model, dated milestones and cut order become phases with exit criteria and soft markers (PLAN §7).
- **DEMO build flavour** becomes the hidden Developer screen (D-73).
- **Docs.** v1's seven large documents become a smaller set (D-96), and v1 stays in git history.
