## 0. Principles

1. **Test what protects correctness.** Feed rules, time zones, ids, signing, the outbox and the PSF guard get thorough, fast tests. Screens get a few journey flows, not a test per feature id (D-04).
2. **One obvious tool per layer.** pytest (+ hypothesis) for logic, `httpx.MockTransport` over the mock's `handle()` for the API, `flet test` and Maestro for UI, each for what the other cannot do (D-252). No Node, jsonschema or snapshot libraries.
3. **API evidence is not device evidence.** Device behaviour is proven by spikes, flows and the phase checklist (D-79).
4. **No test-only code in the app.** Flows use the real UI, including the Developer screen (D-73). Unit tests inject `now`, `httpx` transports and temporary directories.
5. **Measure, don't gate, what CI cannot see.** Device performance and accessibility are measured at phase exits and recorded in the phase status issue (D-79, D-80).

## 3. Unit tests

### 3.1 Conventions

- **Descriptive names** (`test_lunch_row_spans_earliest_start_to_latest_end`). A feature id may appear in the docstring; nothing enforces it (D-04).
- **A docstring on every test** that says, in one sentence, the behaviour it pins; fixtures, helpers, test classes and methods have docstrings too, and `ruff`'s `D` rules check `tests/` (D-253).
- **`core` takes `now` as an argument** (D-43), so tests pass fixed aware datetimes. Only `clock.now()` itself is tested with its override.
- **No network, ever.** A request reaches a server only through a test's `httpx.MockTransport`. The autouse `no_network` fixture (`tests/conftest.py`, #539) makes httpx's own transports raise `ConnectError` instead of connecting and fails at teardown the test that tried one, even when the code swallowed the error. Its one opt-out is the `loopback` marker, which lets a test's httpx reach `127.0.0.1` and nothing else, for a server the test runs itself (the mock's LAN server, `tests/test_mock_api_server.py`, #666). A screen test whose status strip would start the automatic refresh (D-40) replaces the strip or the refresh, as `tests/links.py` does.
- **No network, no Flet runtime.** `core/` tests import no Flet (D-68). Stores are plain `@ft.observable` dataclasses and run without a page; `Observable.subscribe(fn)` checks that a change notifies. `subscribe` holds listeners weakly (a `weakref.WeakSet`): in tests bind the listener to a local name (`def on_change(sender, field): ...`) and keep it alive for the test; never pass a lambda, which is collected at once and never called.
- **Hypothesis** runs derandomised in the full checks and CI (`--hypothesis-profile=ci`): hypothesis's built-in `ci` profile (no deadline, no example database, `too_slow` health check off, `@reproduce_failure` blob printed), which `tests/conftest.py` extends to 200 examples per property; `tests/test_hypothesis_profile.py` pins those values. `tools/check.sh` and CI name the profile on the command line instead of leaving it to the `CI` variable, which hypothesis also reads. Local runs use the `dev` profile, which `tests/conftest.py` loads: hypothesis's defaults (100 random examples) without the 200 ms deadline per example, which a Mac busy with builds and emulators overran in a correctness property (now in `test_html_md_text.py`, 268 ms); speed is measured on devices (§8), not by a property's deadline. `--hypothesis-profile=ci` overrides it, also to reproduce a CI failure.
- **Components and screens in a real Flet session: one harness in two modules** (`tests/sessions.py` and `tests/harness.py`, #204, #253, #286, #623). `rendering(root)` (`tests/sessions.py`) renders a component in a `Session` on a connection to no client, as Flet's own component tests do; `showing(screen, *modules, ...)` (`tests/harness.py`) renders a screen over a feed under the store providers in `App`'s order (`provide()`), with the memory fakes' services (`memory_services()`), each module's `AppScaffold` replaced by a row of its actions over its body (its floating button under it, its re-tap action recorded), `page.navigate` recorded and each session or notice row body counted (D-153), and yields a `Shown` with the lookups (`node()`, `nodes()`: a key ending in a dot names a family of identifiers, any other key a whole one), the SnackBars and dispatched events. A test sets what the screen opens on: its `prefs`, `favorites` not loaded yet, ids `saved` in the storage, a view `memory` kept across sessions, the page's `route`; with `view_path=None` the screen is a real Router, rendered as the page's Views and answering its own View paths, as search's tests use it. Several screens may be open at once in a test: each records its own titles and row bodies and reads its own View path, the stand-ins routing each call by the session Flet binds to the context for its renders and events (`tests/test_sessions.py` opens two and taps a star in each). A screen test adds only what is its own, in a `Shown` subclass it passes as `kind` (a `functools.partial` of it for fields set before the first render) and that its own stand-ins find with `current()`: Now's held clock and minute ticks, the Schedule's recorded scrolls and jumps, My schedule's minute hook, the room's recorded scroll and held highlight, search's searches, focus asks and held debounce (`tests/timers.py`); the rows' list owner and stars (`tests/row_sessions.py`), session detail's in-place re-render (`tests/session_detail.py`). Every screen test in a Flet session uses it, so the two modules that name the Flet internals it uses are the only ones a pin bump (D-81) that renames one breaks.

The limit binds test modules as it binds `src/`, with no exception: a module over it is split in a PR of its own, a few modules at a time and only modules no open PR edits, so a split never conflicts with other work; none is over it since #623. What the parts share goes into one narrow support module (`tests/chrome.py`, `tests/strip.py`), not into `conftest.py`, which keeps the fixtures any module may use: fixtures such as `hooks` differ under one name from family to family. A test module takes a support module's fixtures by assigning them to its own names, where pytest looks a fixture up (`year, svc, page, conference, hooks = (chrome.year, ...)`); importing them would work too, but ruff reads an imported fixture as unused and each test's parameter as its redefinition (F401, F811). A fixture finds the fixtures it takes by name in the same module: both `hooks` take `svc` (which takes `year`) and `conference`, so a module that assigns a `hooks` assigns those three too, or pytest stops with "fixture 'svc' not found".
- **Fast.** The whole suite stays under 2 minutes in the full checks (D-84, §12). A slow test is a design smell, not a reason for a marker.
- **Wait for what should happen, never for a time** (#237). An async test awaits an event, or polls a condition with a generous deadline (`Shown.until` in `tests/schedule_view.py`, `Room.until` in `tests/room_view.py`: 30 s, which a passing test never reaches), so a loaded host only makes it slower. A fixed `asyncio.sleep` is fine only where its length cannot change the outcome: a window for something that must not happen, or a stand-in's latency. The app's own timeouts that a stand-in answers (`scrolling.LANDING_S`, the Schedule's `SETTLE_S`) are set long in tests, and a test checks what the app did (which jumps ran, where they went), not how many times a call that retries asked. A state that lasts only for one of the app's waits (search's debounce, the room's highlight) is never checked against a short real timer, which a loaded host lets fire first (#270): the test holds the wait with `tests/timers.py`'s `HeldSleeps`, which stands in for that screen module's `asyncio`, checks the delay asked for and the state, then releases it; or, when only the end matters, sets the timeout short and checks the end alone. A stand-in that answers at once answers before the app starts its wait (`test_scrolling.py`'s scroll end), so a short timeout cannot race it.

### 3.2 Two machine time zones

Code that is correct only in Pacific time is wrong. Time-sensitive modules (`test_timefmt.py`, `test_feed.py` and `test_feed_records.py`, `test_queries.py`, `test_timeline.py` and `test_timeline_tracks.py`, `test_agenda.py` and its parts, `test_search.py`, `test_search_feeds.py`, `test_row_views.py` and `test_row_views_phrases.py`, `test_rooms.py`, `test_ics.py`, `test_reminders.py`) run every test under two machine zones far apart (D-43), without a CI matrix:

```python
# tests/conftest.py (excerpt)
@pytest.fixture(params=["America/Los_Angeles", "Pacific/Kiritimati"])
def machine_tz(request: pytest.FixtureRequest) -> Iterator[str]:
    """Run the test with the process time zone set to each value in turn (D-43)."""
    with pytest.MonkeyPatch.context() as patch:  # restores only TZ, never another fixture's patches
        patch.setenv("TZ", request.param)
        time.tzset()
        yield request.param
    time.tzset()
```

Each of those modules starts with `pytestmark = pytest.mark.usefixtures("machine_tz")`. Ruff's `DTZ` rules catch naive datetimes statically.

**Snapshot of our model.** A compact, reviewable outline of the processed model is compared with `tests/fixtures/snapshots/outline-<year>.json`: days → groups (by conference-local `HH:MM`) → one line per session, `id | name | track | shown location | start-end`, then `shown HH:MM`, `pre-registration`, `español`, `speakers <ids>` and `text <names not in the directory>` when they apply; then the sessions outside the timeline (poster details), the rooms with their counts, the speaker directory, the drop counts and the skipped records; last, `markdown`: every content block's Markdown and the first value that conversion changed of each other converted field, one Markdown line per JSON string (D-140); then `sponsors`: the levels in order, each `<level> (<order>)` with one `slug | name` line per sponsor, then `booth <n>`, `table <t>`, `banner` and `website <url>` when they apply (D-261). The outline function, `outline()`, lives in `tools/feed_outline.py`, which the stable-ids invariant of `tools/feed_invariants.py` imports to compare two outlines (D-261); a full `dataclasses.asdict` dump would be too large to review. It runs under both machine zones, so it also proves the model does not depend on the machine's zone. When a parser change alters the outline, the PR runs `uv run pytest tests/test_feed_invariants.py --snapshot-update` and explains the diff in its body.

```python
# tests/conftest.py (excerpt)
import json
from pathlib import Path

import pytest

SNAPSHOTS = Path(__file__).parent / "fixtures" / "snapshots"


def pytest_addoption(parser):
    parser.addoption(
        "--snapshot-update",
        action="store_true",
        help="Rewrite snapshot files instead of comparing with them.",
    )


@pytest.fixture
def snapshot(request):
    """Return check(name, data): compare data with a committed JSON snapshot."""
    update = request.config.getoption("--snapshot-update")

    def check(name: str, data: object) -> None:
        path = SNAPSHOTS / f"{name}.json"
        text = json.dumps(data, indent=1, sort_keys=True, ensure_ascii=False, default=str) + "\n"
        if update:
            path.write_text(text, encoding="utf-8")
            return
        assert path.exists(), f"No snapshot {path.name}; run with --snapshot-update and review it"
        assert path.read_text(encoding="utf-8") == text, (
            f"{name} changed; review the diff, then run with --snapshot-update"
        )

    return check
```

## 4. Signing, the mock server and the outbox (P3)

### 4.1 Signing vectors (D-52)

`tests/fixtures/ionic/signing.json` holds vectors produced once by Ionic's own `buildRequestAuthHeaders` (`providers/pycon-api.ts`, copied unchanged) under Node, with a stubbed `Storage` (made-up key and secret) and a fixed `Date.now()`, and its provenance (Ionic commit, `sha1-uint8array` 0.10.7 from Ionic's lock file, esbuild, Node, npm, date). `tools/capture_ionic_reference/capture_signing.py` makes it; its README says how. Client and mock share `core/signing.py`, so only outside vectors catch a shared mistake. `tests/test_signing.py` rebuilds each case's path and body with `enc` and `canonical_body`, then checks the timestamp, the signature and the three headers. Cases, each named:

- an empty-body GET; a query `encodeURIComponent`-encoded (lead capture, with every character `encodeURIComponent` keeps or escapes) and one Ionic leaves unencoded (`fetch_products`, its comma kept);
- the same lead-capture query with its parameters in another order (a different signature);
- JSON bodies with non-ASCII text (an emoji outside the BMP included), quotes, backslashes, slashes, `\n`, `\t`, a control character and U+2028; a boolean; insertion-ordered dynamic keys (`product-redeem-<id>`, numbers unquoted);
- timestamps at x.499, x.500 (x even and odd) and x.501 seconds (`Math.round(Date.now() / 1000)`, where Python's `round` goes to even);
- signed out: Storage returns null for the key and secret, and `join` renders `''`.

The tests also pin the four `hashlib` vectors of architecture §10.3 and `js_round` against `Math.round` at and just below halves. Node never runs in CI or `tools/check.sh`.

### 4.2 Mock API tests (D-50, D-57)

`MockState` holds the state seeded from `tests/fixtures/mock/seed.json`, and D-50's pure `handle(state, method, path, headers, body) -> (status, headers, body)` serves it. Tests call `handle` directly (signature and timestamp window, each endpoint's reply shape, bare or `{code, data}`, and the error bodies from `tools/mock_api/README.md`, role accounts) and through the real client, using `tools/mock_api/transport.py` (architecture §11):

```python
# tools/mock_api/transport.py (excerpt)
import httpx

from tools.mock_api.handlers import handle
from tools.mock_api.state import MockState


def mock_transport(state: MockState) -> httpx.MockTransport:
    """Route the client's requests to the in-process mock."""

    def respond(request: httpx.Request) -> httpx.Response:
        status, headers, body = handle(
            state, request.method, request.url.raw_path.decode("ascii"), request.headers, request.content
        )
        return httpx.Response(status, headers=headers, content=body)

    return httpx.MockTransport(respond)
```

The client's own tests (#665) go through the same transport: `tests/test_api_client.py` round-trips every endpoint (the mock checks each signature over the bytes sent), the two errors and `is_auth`, and the skew retry (the mock's clock moved 900 s after sign-in: one corrected retry, remembered for later calls; a refused retry is final; an unsigned call or a 403 without a `Date` is never retried); `tests/test_api_endpoints.py` checks the endpoint table against the README's rows and the mock's routes, each request's timeout, and that the client sends Ionic's own target, body and headers for eight of the §4.1 vectors (the `fetch_products` path among them); `tests/test_api_guard.py` is the PSF guard (§3).

Faults are raised by the transport or set on the mock, never by code in the app. A test switches one on with `state.faults.inject(name)`, for the next request or with `until_cleared=True` until `state.faults.clear()`; `tests/test_api_faults.py` holds the client-level scenarios (#667), and the server takes the same faults from `--fault` (development.md §6):

| Fault | How | Expected client behaviour |
|---|---|---|
| Connection refused (`connect`) | transport raises `httpx.ConnectError` before `handle` | `NetworkError` with `maybe_sent` False; outbox tries not counted, row not flagged |
| Connect timeout (a test's `Wire.before` raises `httpx.ConnectTimeout`) | the request never leaves | as `connect`: not flagged |
| Timeout (`timeout`) | transport raises `httpx.ReadTimeout` before `handle`; per-endpoint timeouts match Ionic's table (API-12) | `NetworkError` with `maybe_sent` True: a read timeout can come after the server had it, so the row is flagged though this mock recorded nothing |
| Server committed, response lost (`lost_response`) | transport calls `handle`, then raises `httpx.ReadError` | `NetworkError` with `maybe_sent` True; row stays pending and is flagged "may be recorded twice" for good (D-410); the retry must not duplicate under idempotent semantics (below) |
| Expired auth (`revoked`) | mock answers 401 for every signed call | `ApiError.is_auth`; sign-in prompt; queue kept |
| Skewed clock (`MockState.skew`) | mock clock offset, 900 s in the tests | skew learned from `Date`, one retry, then success |
| Account or sponsor switch with rows pending | changed between syncs | rows keep owner and sponsor snapshot |

**Both capture semantics.** Sync tests are parametrised over `MockState(capture="idempotent")` and `"non_idempotent"`. Idempotent: every record is stored exactly once. Non-idempotent: a lost response plus a retry can create a second server record, which no client can prevent, so the test asserts what the client guarantees: never lost, never misattributed, one local synced row, and every duplicate traced to an ambiguous failure in the mock's log (§14). `tests/test_sync_faults.py` (#693, D-410) is that check: a lost answer on a lead capture or a door redemption under each semantics flags exactly that row ("Confirmed · may be recorded twice", idempotent included, since the client cannot tell), every row the mock recorded twice is a flagged one, and `connect` or a connect timeout flags nothing and records each row once.

### 4.3 Outbox (D-56)

A hypothesis `RuleBasedStateMachine` (`tests/test_outbox_machine.py`) drives the pure rules in `core/outbox.py` with rules for enqueue (lead, note, door), sync success, network failure (before the request left, or a lost answer), server failure (one, or a streak of up to 10), sponsor switch, account switch, time passing and "Retry failed". Invariants after every step:

- no unsynced row is ever lost, an account switch included;
- a row's owner, sponsor snapshot, kind, code, idempotency key and scan time never change after enqueue; a note keeps its lead's sponsor;
- only rows sent successfully are synced, and a synced row is never due again;
- network failures never increase `tries`; a row is `failed` exactly at 10 counted failures;
- a row is flagged `maybe_sent` ("may be recorded twice") exactly from its first lost answer on, whatever follows (D-410);
- a note is never due before its lead is synced, and its lead row is kept while it waits;
- one lead and one note row per (owner, code); at most one door row per (code, products, session).

The machine records each row's attribution at enqueue time, and what it expects of `tries` and the status, and compares them in `@invariant()`s; `TestOutbox = OutboxMachine.TestCase` exposes it to pytest. Each row of architecture §12.2's table, and `due()`'s order, is a plain test in `tests/test_outbox.py`. The sqlite layer (`services/`) gets plain tests on a temporary file: rows survive closing and reopening the connection mid-sync; `PRAGMA user_version` migrations run from every earlier version; WAL mode is on.

### 5.2 Driving state without test hooks

- **Identifiers.** Key controls carry `Semantics(identifier="<screen>.<element>[.<key>]")` (D-33, §M), e.g. `schedule.favorite.42`, `now.next_session`. They become Android `resource-id` and iOS `accessibilityIdentifier`, so they never contain names, emails or badge codes. Plain string literals; a typo fails a flow.
- **The Developer screen** (D-73) sets the scene; flows unlock it with 7 taps on the version row (`about_app.version`), as a person would, then the **Developer options** row it adds (`about_app.developer`; #88, D-187). It has `developer.fake_clock` (ISO 8601 text; without an offset it is conference time), `developer.feed_url`, `developer.apply`, `developer.reset` (back to real time and the year's feed, no confirmation) and `developer.outcome`, the line that says what is in effect; the Data section (#107, D-198) has `developer.refresh_now`, `developer.clear_cache`, `developer.share_log`, `developer.show_welcome` (Welcome again, keeping the settings and saved sessions; #424) and `developer.reset_app`, whose confirmations' buttons are `<row>.confirm` and `<row>.cancel`, and `developer.data_outcome`; `developer.mock_url` comes in P3. A flow that needs a clean slate in the middle of a run can use Reset app › Reset app, which leaves the app as after a fresh install, on Now. A test build is a fresh install (§5.1), so a flow starts locked, on real time and on the year's feed.
- **Data.** The `feed_url` fixture (in `tests/ui/conftest.py`) serves `tests/fixtures/feeds/` from the laptop with `http.server.ThreadingHTTPServer` on `127.0.0.1` and returns the URL the app can reach: `http://10.0.2.2:<port>/conference-2026.json` on Android, `http://127.0.0.1:<port>/…` on iOS. "Offline" is the `silent_feed` fixture (`SilentFeed`, in `tests/ui/feeds.py`): a server on the laptop that takes each request and hangs up unanswered, which the app reads as no answer; real airplane mode would also cut the tester's socket. It counts the requests it takes, and `hold()` keeps the next ones open until `hang_up()`, so a flow sees a refresh it asked for run ("Updating the schedule…") and end, where a refused connection on a closed port can start and end between two polls (D-223). A change-log pair is `PairFeed`, in the same module: the old feed at one URL until `swap()` (or `POST /swap`), then the new one (§9.2, #460). F2–F5 run on the recorded feed at 09:00 the day before the conference (`before_conference()`): the Schedule opens on its first day at the top, with no jump to now (D-192, D-204), so the rows a flow taps are on screen. What a flow looks for comes from `tests/ui/targets.py`, which processes the recorded feed (`recorded()`) or the bundled snapshot (`bundled()`) with the app's own code and lists a day's rows as the Schedule shows them, with the default filter, which hides open spaces (`day_rows()`, D-20); no id is written out (D-223).
- **Which screen.** A `Finder` only counts matches, and a root's title also shows as its tab's label, so each tab root's app-bar title carries `<tab>.title` (`now.title` … `more.title`, D-170); a pushed View is known by its back arrow (`find_by_tooltip("Back")`) and by the bar's absence (D-144).
- **Back.** Both platforms: tap the app bar's back arrow (`tap_back_arrow`). Android also: the Back key, `adb -s $FLET_TEST_DEVICE shell input keyevent KEYCODE_BACK` from the test (`press_system_back`). The iOS edge swipe and Android predictive back stay manual (§9).
- **Settling.** Indeterminate progress and shimmer never settle, so helpers poll with `pump(duration)` until a finder matches, or stops matching. While a push or a pop runs, both Views are on screen, and a tap on the one leaving is lost: a flow waits for the leaving View's marker to be gone, and `tap_back_arrow` for exactly one back arrow (#78 lost a tap that way). Android emulators run with the three animation scales at 0 (`adb shell settings put global transition_animation_scale 0`, etc.); Flutter reports that as `disable_animations`, which the app honours (D-34). `RemoteTester.pump(duration)` does not wait that long in real time on a device: a tap after `pump(1 s)` reached a SnackBar 5 dp into its 250 ms entrance on the iOS simulator and missed its Undo (#197). So a tap that an animation can swallow, on a control that acts once (a SnackBar's Undo), is repeated until its effect shows (`tap_until`), rather than after a fixed sleep (D-223); `test_snackbar_on_pushed_view.py`'s `settle()`, which sleeps and then pumps, predates it.

### 5.3 An example flow

F4, `tests/ui/test_favourite_undo.py` (#108), without its docstrings:

```python
async def test_favourite_with_undo(flet_app: ftt.FletTestApp, feed_url: str) -> None:
    t = remote(flet_app)
    await fresh_start(t, now=before_conference(), feed_url=feed_url)
    session = saveable(day_rows(recorded(), 0))[0]  # the first row with a star
    saved_row = row_id("my_schedule", session)

    # Star it on the Schedule; My schedule lists it.
    await tap_id(t, "app.nav.schedule")
    await tap_id(t, star_id("schedule", session))
    await tap_id(t, "app.nav.my_schedule")
    await wait_for_id(t, "my_schedule.title")
    await wait_for_id(t, saved_row)

    # Unstar it there: the row goes, the SnackBar offers Undo (D-30).
    await tap_id(t, star_id("my_schedule", session))
    await wait_for_text(t, REMOVED)
    await wait_for_id(t, saved_row, gone=True)

    # Undo saves it again, and the row is back.
    await tap_until(
        t,
        lambda: t.find_by_text("Undo"),
        lambda: t.find_by_semantics_identifier(saved_row),
        "Undo",
    )
```

Shell controls (the navigation bar, app-wide chrome) use `app.<element>[.<key>]`, such as `app.nav.schedule` (decisions §M). The flows run on phones in portrait, where the bar shows; from 600 dp the rail replaces it, and its destinations have no identifier yet (#163, D-277): a flow there finds one by its name, "Map, Tab 4 of 5" (Maestro: `tapOn: "Map.*Tab 4 of 5"`).

simulator's network, so there the launch's refresh may publish the year's live feed. A fresh iOS install
that never reaches the feed is set up by writing that URL into the app's container
before its first launch (`maestro/README.md`, "Offline on a fresh iOS install").

**Caveats.**
- On Android, any read of the accessibility tree makes Flutter report a screen reader
  (F72), so under Maestro the app takes its screen-reader paths: the Schedule keeps its
  Now button (D-204), and by D-184 SnackBars stay until used. `jump_to_now` checks the
  button on iOS only; no flow checks a SnackBar's timeout.
- About 0.85 s passes between two Maestro commands on the emulator, so the regression
  flow's fling comes 0.8 to 1.0 s after the tap. #346 saw its failures at 0.33 to 0.6 s;

  window is reached by `tools/fling_after_sheet.py` (Android): it sends the tap and the
  fling in one `adb shell` command, measures the gap from the launcher's touch log, and
  judges each fling by the flow's rules. It refuses a run that does not start on the now
  slot, 2:00 PM, and counts a trial whose gap is missing or outside 330 to 600 ms as "off
  window", a failure that says nothing about row D. Its first runs (`maestro/README.md`),
  counted before that rule, have not yet told #346's build from `main`: both lost flings
  only during load spikes, at gaps past the window.
- The app bar's back arrow has no identifier: Android flows press the system Back, iOS
  flows tap the button named "Back".

**When they run.** The journeys locally before merging a PR that changes one (one
platform), and at every phase exit and Flet pin bump on both platforms, with the device
checklist (§9). A regression matrix runs on a PR that touches what it guards, against
`main`'s build on the same device.

## 7. Accessibility checks (D-33)

### 7.1 Automated: contrast

A unit test checks every declared text/background pair in each scheme: light and dark from P0 (`tests/test_theme.py`, the badges and tokens in `tests/test_theme_badges.py`, the Markdown style sheet in `tests/test_theme_markdown.py`), high contrast from P2 (`tests/test_high_contrast.py`, which also checks that HC leaves no role unset, that its text roles read at 7:1 on every surface and that both outlines read at 3:1). Text needs 4.5:1, or 7:1 in high contrast. Track badges and `Tokens` (`live`, `warning`, `success`, `favorite`) are checked the same way: a tonal badge's label on its fill, and the outlined "Registration required" badge's label on every surface of the neutral ramp, since it has no fill of its own (D-174). A test also checks that every `Tokens` field is one of the two kinds, and that every track key of every year has its own pair. Now's elapsed bar (D-190) is checked on the list's `surface` and on the next-session card's `surface_container_highest` in both schemes: the `live` fill reads 3:1 or more on its track (`on_surface` at 16 %, about 1.4:1 on either surface, a hint only), and M3's stop dot, in `on_surface_variant` (4.5:1 or more), marks where 100 % is (WCAG 1.4.11). Each brand mark's tint (`ui/brands.py`, D-264) reads 3:1 or more on every surface of `brands.BRAND_SURFACES` (the page's `surface`) in both schemes, a role tint (X's `on_surface`) resolved per scheme (`tests/test_brands.py`); a mark placed on another surface adds it there first.

Roles left to the seed are computed by Flutter's `ColorScheme.fromSeed` on the Dart side (F9), so Python cannot check them. Hence one rule, also enforced by the test: **an overridden role is always declared with its "on" partner**. Seeded pairs are spot-checked on screen with Accessibility Scanner (§7.3). Light and dark also declare `surface`, `on_surface` and `on_surface_variant` (the values of Flet's neutral ramp) and `error` / `on_error` (the seed's own, D-174), and the test checks those text roles, `primary` (links) and the tokens on every surface of that ramp (`surface`, `surface_bright`, `surface_dim` and the five `surface_container*`), mirrored from `neutralizeSurfaces` in Flet's `utils/theme.dart`, since cards, sheets, bars and Markdown code spans sit on them.

```python
# tests/test_theme.py (excerpt)
import pytest

from pycon_us.theme import build_theme

PAIRS = [
    ("primary", "on_primary"),
    ("primary_container", "on_primary_container"),
    ("secondary", "on_secondary"),
    ("secondary_container", "on_secondary_container"),
    ("tertiary", "on_tertiary"),
    ("tertiary_container", "on_tertiary_container"),
    ("error", "on_error"),
    ("surface", "on_surface"),
    ("surface", "on_surface_variant"),
]


def luminance(hex_color: str) -> float:
    """Relative luminance of #RRGGBB, as defined by WCAG 2.x."""
    channels = [int(hex_color.lstrip("#")[i : i + 2], 16) / 255 for i in (0, 2, 4)]
    r, g, b = (c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4 for c in channels)
    return 0.2126 * r + 0.7152 * g + 0.0722 * b


def contrast_ratio(a: str, b: str) -> float:
    lighter, darker = sorted((luminance(a), luminance(b)), reverse=True)
    return (lighter + 0.05) / (darker + 0.05)


@pytest.mark.parametrize("dark", [False, True])
@pytest.mark.parametrize("high_contrast", [False, True])
def test_declared_colour_pairs_are_readable(dark, high_contrast):
    scheme = build_theme(dark=dark, high_contrast=high_contrast).color_scheme
    minimum = 7.0 if high_contrast else 4.5
    for background, foreground in PAIRS:
        bg, fg = getattr(scheme, background), getattr(scheme, foreground)
        assert (bg is None) == (fg is None), f"{background} overridden without {foreground}"
        if bg is not None:
            assert contrast_ratio(fg, bg) >= minimum, (background, foreground)
```

### 9.1 Real-time checks: a feed shifted to now (#383)

The Developer fake clock moves what the app shows, but the OS fires a reminder at a real instant, so a May session cannot be checked in October. `tools/shifted_feed.py` writes the bundled snapshot shifted so that a chosen session starts a few minutes from now, for item 12, Now's "Your next session" and the change log at real times, with no fake clock:

```sh
uv run python -m tools.shifted_feed 142 --in 5m --move 15m   # session 142 starts 5 min after this minute
uv run python -m http.server 8765 --bind 127.0.0.1 --directory build/shifted-feed   # as it prints; keep it running
```

- **On the device:** in Developer options, empty the fake clock, set the feed URL it prints, `http://10.0.2.2:8765/conference-shifted.json` on the Android emulator or `http://127.0.0.1:8765/conference-shifted.json` on the iOS simulator, Apply, then Refresh now; save the session. Both addresses are the Mac's loopback, so a physical phone cannot reach them.
- **What moves:** every slot's and open space's `start` and `end`, by one delta of wall-clock time in the conference zone (D-43), so 9:00 stays on the hour and each offset is its new date's. The chosen session is set from instants instead, so on the night summer time ends it starts at the right one of the repeated hour's two 1:25s. Session ids stay, so saved sessions stay saved; the Break, Lunch and Posters rows' ids carry their start, so theirs change.
- **What does not:** `conference.toml` keeps May's dates, so the Schedule's days run from the year's first day to the shifted ones (`days()` widens to the feed's, DATA-17); and a delta that is not whole days moves each day's late sessions past midnight into the next date. Check Now, reminders and session detail with it, not the Schedule's days.
- **Its guard:** before writing, it runs every invariant of `tools/feed_invariants.py` on each file, against the year's dates shifted by the same delta (the first day from its midnight, the others from their last moment), and writes nothing when one breaks. It also refuses an `--in` whose delta moves a time into the hour skipped when summer time starts, which does not exist. A moved session may span the end of summer time: the app reads and compares session times as instants (#513, #535; `tests/test_dst_instants.py`).
- **A schedule change:** `--move 15m` (or `-10m`) also writes `conference-moved.json`, the shifted feed with only that session's `start` and `end` moved. Serve it at the same URL (`cp` it over `conference-shifted.json`, as printed), since a feed URL change deletes the cache and the change log (D-255), then Refresh now: the app diffs it as it would a real move.
- The files go to `build/shifted-feed/` (`--out` to change it; `build/` is ignored) and are never committed.
- **Timing:** a session reminder fires its lead (5 min at least) before the start, so `--in 8m` leaves about three minutes to refresh and set the scene; with less, the reminder is already past when the plan applies (`a plan of N applied` in the log: logcat's `flet.python` on Android, `Library/Caches/console.log` in the app's container on the simulator).
- **Tapping a reminder (#459):** on the iOS simulator, with the app terminated or in the background, Maestro's `extendedWaitUntil` on the banner's text, then `tapOn` that text, opens it: SpringBoard is in front, so its banner is in Maestro's hierarchy. One notification at a time: a tap on a stack of two only expands it (#450). Over the app, the banner is not in the app's hierarchy, so tap it by point (`point: "50%,10%"`) about 6 s after Developer's test reminder. On Android, `adb shell cmd statusbar expand-notifications`, then `tapOn` the text; a collapsed group opens the launcher intent, not the tap (F246). To swipe the app away, recents' **Clear all** (`input tap` on it) kills it as a swipe does (`Killing … remove task` in logcat): on the API 36 AVD neither `adb shell input swipe` nor Maestro's `swipe` dismissed the card.

### 9.2 The change log from a served feed pair (#460)

P2's exit criterion 4 asks for the change log on a device from a fixture feed pair. `tools/feed_pair.py` serves one at a single feed URL from the laptop: the recorded feed of the active year (`tests/feeds.py`'s `recorded()`), and once swapped a copy with named edits (`changed()`, D-255), through `PairFeed` in `tests/ui/feeds.py`, beside `SilentFeed`:

```sh
uv run python -m tools.feed_pair --move 123 "Room 103ABC" --move 142 "Room 101B"   # keep it running
curl -X POST http://127.0.0.1:8460/swap                      # serve the copy; /reset: the recorded feed again
```

- **Edits:** `--move KEY ROOM`, `--retime KEY START END`, `--rename KEY NAME`, `--add KEY LIKE NAME`, `--remove KEY`, each repeatable, by the slot's `conf_key`. Before it serves, it runs the app's parser and diff on the pair and prints the changes the app will find, and refuses a pair in which it finds none (an edit of a break, a move to the same room).
- **On the device:** in Developer options, set the feed URL it prints (`http://10.0.2.2:8460/conference-<year>.json` on the Android emulator, `http://127.0.0.1:8460/…` on the iOS simulator), Apply, Refresh now: the first refresh from a new feed URL is not diffed, so no batch. Save a session the edits touch, swap, Refresh now: the app records the batch as it would a real change. Both addresses are the Mac's loopback, so a physical phone cannot reach them.
- **The flow:** `maestro/journeys/change_log.yaml` (tag `feed_pair`, not `journeys`, since it needs the server) runs those steps with `--move 123 "Room 103ABC" --move 142 "Room 101B"`, from the SnackBar's Review to Now's card gone once seen (on Android, where Maestro makes the app see a screen reader, F72, the item still reads "New: " on the list and is seen once the list is left, ux.md §6.4; #655); `FEED_URL` and `CONTROL_URL` name the server on another port (`maestro/README.md`).
- **The same bytes:** a new feed URL's first refresh that brings the very feed shown publishes nothing (D-224) but makes it that URL's, so the swapped copy is still diffed against it (D-255; before #460 that change was lost when the shown feed was the pair's old side, such as the bundled snapshot after an offline launch).

## 12. Checks and CI wiring (D-84, D-273)

- **Local checks while the repo is private** (D-273; development.md §7): `tools/check.sh` runs `ci.yml`'s steps on the Mac, `--fast` all but pytest. The pre-push hook runs the fast checks on every push that changes more than Markdown; the author runs the full checks before marking a PR ready; the merge gate (`tools/gate.sh <pr> [<pr>...]`) runs them on the PRs merged onto the latest `main` before every merge and posts the result on each PR. Nothing runs them on Linux until P4. The three workflows below run only by hand (`gh workflow run <file> --ref <branch>`) until the PR that makes the repo public brings their triggers back.
- **`ci.yml`** (by hand while the repo is private; every PR and push to `main` once it is public; Linux): `uv sync --locked`, `ruff check`, `ruff format --check`, `pyright`, `pytest --hypothesis-profile=ci` (hypothesis's built-in profile, extended in `tests/conftest.py`, §3.1). Target under 2 minutes. UI flows are excluded by `addopts = ["--ignore=tests/ui"]` (§2).
- **`feed-check.yml`** (by hand while the repo is private, with `uv run python -m tools.check_feed` locally; weekly once it is public): `tools/check_feed.py` runs our parser and the invariants on the current year's public feed, and says whether next year's feed answers yet (a 404 is "not published yet", never a failure). Keys the recorded feeds lack are printed, not failed. Its tests serve the recorded feed, broken copies of it and HTTP errors through `httpx.MockTransport` (`tests/test_check_feed.py`).
- **`build-android.yml`** (manual; `v*` tags too once the repo is public): a debug-signed APK artifact; while the repo is private the quick-look APK is usually built locally. iOS builds and all device work stay local.
- **Not in CI:** flows, goldens, device checks, performance. Spike S9 (PLAN §8; #363, label `test`, P2 at the earliest; it needs GitHub's Linux runners, so it waits until the repo is public, D-273) tries `flet test linux` on `ubuntu-latest` under `xvfb-run` with a phone-sized window. Once it has run green for two weeks, it is proposed as a separate workflow through a `needs-decision` issue, since D-84 fixes three workflows and keeps `ci.yml` under 2 minutes; it never goes into `ci.yml` (D-78).
